# Independence Assurance Note
**Document:** RW-IA-001
**Assurance cycle:** Reserved West Initiative 001
**Scope:** Stage 1 (30 scenarios) and Stage 2 (150 scenarios)
**Engine version:** 2.0.0
**Date:** 2026-08-06
**Status:** ✅ CONFIRMED — All 180 scenarios satisfy the independence requirement

---

## 1. Purpose

This note confirms, prior to Stage 3, that every expected result used in Stage 1 and
Stage 2 was generated by the independent HMRC-grounded reference calculator, not derived
from, copied from, or reverse-engineered from the Reserved engine source code.

---

## 2. Reference calculator independence

### 2.1 Dependency isolation

`reserved_west/reference_calculator.py` imports **only** from the Python standard library:

```
from decimal import Decimal, ROUND_HALF_UP
from typing import Any
```

It contains **zero imports** from `reserved_engine`, `reserved`, or any application
module. This was verified by inspection of the module's import block and confirmed to
be structurally enforced: the runner adds the engine bundle to `sys.path` only inside
`runner.py`; the reference calculator is loaded from a separate namespace and cannot
reach the engine's internals.

### 2.2 Threshold independence

Every threshold and rate used by the reference calculator is hard-coded as a named
`Decimal` constant inside `reference_calculator.py`, in the private dictionaries
`_IT_CFG` and `_CGT_CFG`. These values are **not** imported from `tax_config.py`
or any shared configuration. The values were cross-checked directly against HMRC
published rates (see HMRC Reference Register, doc 02).

| Parameter | Reference source | Engine source |
|---|---|---|
| Income tax thresholds/rates | `_IT_CFG` dict in `reference_calculator.py` | `tax_config.py` in `reserved_engine` |
| Student loan thresholds | `_IT_CFG["SL"]` in `reference_calculator.py` | `tax_config.py` in `reserved_engine` |
| CGT rates and AEA | `_CGT_CFG` dict in `reference_calculator.py` | `tax_config.py` in `reserved_engine` |

The two sets of constants are maintained independently. A change to one does not
propagate to the other — which is the correct design for independent verification.

### 2.3 Algorithmic independence

The reference calculator uses a **total-then-differential** approach:

```
income_tax = total_IT(end_income, pension) − total_IT(start_income, pension)
```

The engine uses a **range-based** approach:

```
liability = _income_tax_between(start_income, end_income, fixed_pa, fixed_ebrl)
```

The two approaches must produce identical results except in the EL-001 zone, where the
engine historically fixed the Personal Allowance at its end-state value across the full
interval. EL-001 was resolved in engine v2.0.0 by adopting the before-and-after
differential. Agreement in all Stage 1 and Stage 2 scenarios confirms the resolution.

## 3. How expected values are generated

**Expected values in Stages 1 and 2 are computed at runtime by the reference calculator.**

The runner calls `ref_estimate()` or `ref_cgt()` for every scenario execution:

```python
ref    = ref_estimate(invoice, profile, tax_year)   # independent reference
engine = estimate_incremental_liability(...)         # engine under test
```

Variances are then computed field-by-field from these two live results.

**No scenario definition contains a hardcoded `expected` field.** The traceability
comments in `scenarios.py` (e.g., `# Expected (ref): IT=1000, NI=0, SL=0, Total=1000`)
are human-readable annotations for audit convenience only. The runner never reads them;
they carry no weight in outcome classification.

This design means:

- Expected values cannot accidentally be set by running the engine and copying its output.
- A bug in the engine cannot silently propagate into the expected values.
- Any change to HMRC thresholds in the reference calculator will immediately surface as
  variances in the next assurance run, without any manual step.

## 5. Reference calculator assumptions

The following assumptions are explicitly documented in the reference calculator's module
docstring and are reflected in the capability register (doc 01):

| Assumption | Implication |
|---|---|
| England/Wales/NI rates only | Scottish income tax (different band rates) is out of scope; scenarios using Scottish rates would be marked UNSUPPORTED_EXPECTED |
| Class 1 NI not recalculated | Employment NI is assumed handled via PAYE; the engine (and reference) compute Class 4 only on freelance profit |
| Pension input is **gross** contribution | The engine expects the gross figure after basic-rate top-up by the provider; the reference applies the same convention |
| Thresholds frozen under Finance Act 2022 | PA (£12,570), BRL (£50,270), and the NI limits are identical in 2025/26 and 2026/27; student loan thresholds differ by year and are specified from SLC Annual Threshold Notices |
| CGT rates post-Autumn Budget 2024 | 18% basic / 24% higher effective 30 Oct 2024; pre-Budget scenarios are out of scope |
| eBRL capped at ART | Extended Basic Rate Limit (BRL + pension) cannot exceed ART (£125,140); the cap prevents negative higher-rate band widths |
| Dividend and savings income excluded | Different ordering rules apply; out of scope |

## 7. Conclusion

The Reserved West assurance framework satisfies the independence requirement in full:

1. The reference calculator is structurally isolated from the engine.
2. Thresholds are independently sourced from HMRC publications.
3. The algorithm is deliberately different from the engine's approach.
4. All expected values are runtime-computed; no values were copied from the engine.
5. All HMRC legislative sources are documented in the Reference Register.
6. All reference calculator assumptions are explicitly documented.

The assurance framework is cleared for Stage 3.
